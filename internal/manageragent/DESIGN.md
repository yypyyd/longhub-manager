# Manager Agent 设计

## 设计目标

1. 在 OpenClaw Gateway 不可用时仍能运行诊断 Agent。
2. 模型只能调用代码中注册的固定工具，不能构造命令或路径。
3. 只读检查可自动执行，任何本机写操作都需要用户逐次确认。
4. 模型配置、API Key、命令输出和会话资源都有明确边界。
5. 工具结果必须可追溯，Agent 不得声称执行了没有结果支持的动作。

非目标包括通用聊天平台、持久化会话、远程控制面、任意 MCP/Shell 工具，以及替代 OpenClaw 自己的 Agent 系统。

## 架构

```text
WebView 页面
   │ 本机 Bearer API
   ▼
httpapi ── Engine ── ModelClient ── 用户配置的模型服务
   │          │
   │          └─ 内存会话 / 待确认状态
   ▼
固定 ToolExecutor ── runtime / configbackup
```

- `ConfigStore` 保存非敏感模型配置，并通过 `SecretStore` 保存 API Key。
- `ModelClient` 实现有限的 OpenAI Responses 和 Chat Completions 兼容请求。
- `Engine` 维护消息、工具循环、审批和会话生命周期。
- `ToolExecutor` 是信任边界：只有注入的 `ToolSpec` 会暴露给模型。

## 关键流程

### 配置与凭据

模型地址必须是 HTTPS；仅 `localhost` 和 IP 回环地址允许 HTTP。地址禁止用户信息、查询参数和片段。Windows 构建使用 Generic Credential `LongHub/ManagerAgent/APIKey`，普通 JSON 配置从不包含 API Key。

保存时先原子写入新配置，再写系统凭据；凭据写入失败会恢复原配置。删除时先移除配置，再删除凭据；凭据删除失败也会恢复配置，避免产生半完成状态。

“已保存”只表示字段和凭据完整，不代表模型可用。页面保存后会用相同模型、
Bearer 凭据和完整工具定义执行无副作用连接测试。失败时返回经过长度限制、
API Key 替换和用户目录脱敏的供应商错误，用于区分无权限模型、错误 Key 和协议不兼容。

协议可显式选择 Responses 或 Chat Completions，默认自动模式对路径中的 `codex`
分段选择 Responses，其余地址保持 Chat Completions 兼容。Responses 工具回合会在
内存会话中保留限长的 `message`、`function_call` 和 reasoning 状态项，以便将
工具结果正确续传给推理模型；这些状态不持久化也不返回 WebView。

### 工具审批状态机

```text
用户消息 → 模型
             ├─ 普通回答 → 完成
             ├─ 只读工具 → 执行 → 工具结果 → 模型
             └─ 写工具 → Pending Approval
                            ├─ 同意 → 执行 → 结果 → 模型
                            └─ 拒绝 → 拒绝结果 → 模型
```

待确认期间同一会话不接受新消息。审批 ID 使用加密随机数生成，并且只对当前待确认调用有效。用户拒绝后不会执行工具。

### 实时对话事件

`TurnWithEvents` 与 `ResolveApprovalWithEvents` 在实际状态转换发生时同步发出事件：模型轮次开始、
检查计划生成、工具开始、工具成功/失败、等待审批和答案生成。HTTP 层通过仅限本机鉴权的 SSE
接口逐条刷新 WebView，最终回答以限量文本片段进入同一个对话流。事件不包含模型 reasoning、
工具原始输出、绝对路径或凭据；普通 JSON 接口继续保留用于兼容和非流式调用。

### 资源限制

- 用户消息最大 8 KiB。
- 模型响应最大 2 MiB，工具参数最大 16 KiB。
- 工具结果最大 32 KiB，并在 UTF-8 边界截断。
- 单次最多连续 12 轮工具调用；独立只读检查要求模型同轮批量请求。
- 达到工具轮次预算后关闭工具能力，强制模型基于已有结果生成总结；模型总结失败时返回确定性的安全摘要，不让页面停在“执行中断”。
- 最多 32 个内存会话，会话 6 小时过期，每个会话最多保留 80 条消息。
- 模型请求默认超时 90 秒，HTTP 重定向始终拒绝，防止 Bearer 凭据被转发。

## 方案选择与权衡

### 独立 Agent，而不是复用 OpenClaw Gateway Agent

复用 Gateway 的实现更少，但 Gateway 损坏时无法工作，违背管家的核心用途。当前方案增加一个小型模型客户端，只实现工具调用所需协议。

### 内存会话，而不是本地数据库

内存会话在 Manager 重启后丢失，但不会在磁盘留下诊断内容或用户消息，也避免引入数据库迁移和清理风险。运维对话应当短期、可重建，因此接受该权衡。

### 工具白名单，而不是通用命令执行

通用 Shell 能覆盖更多故障，但模型提示注入会直接获得主机执行能力。固定工具将参数解析、命令和确认策略保留在可信代码中，是不可放宽的边界。

### OpenAI 兼容接口，而不是绑定单一厂商 SDK

兼容接口便于用户选择模型服务且依赖小；代价是目前要求服务支持 Chat Completions 工具调用，不直接实现各厂商私有协议。

## 威胁模型与安全措施

- **恶意或被注入的模型输出**：未知工具被拒绝；参数必须匹配 JSON 对象并由具体执行器再次严格解析。
- **未经授权的写入**：所有 `RequiresApproval` 工具都会暂停，页面确认前没有副作用。
- **API Key 泄漏**：Key 与配置分离、不返回页面、错误消息替换精确 Key、模型请求禁止重定向。
- **资源耗尽**：限制请求、响应、工具输出、会话数量和循环轮次。
- **本机信息外发**：inventory 在进入模型前递归脱敏密钥字段、凭据样式和用户主目录。用户仍应只配置其信任的模型服务。
- **工具失败后虚假成功**：错误与已有结构化结果一起返回模型，步骤状态明确标为失败。

## 已知限制

- 仅支持 OpenAI Responses 和 Chat Completions 兼容工具调用，不实现各厂商其他私有协议。
- 会话不跨 Manager 重启恢复。
- 模型服务的隐私、保留和可用性由用户选择的服务决定。
- 当前审批粒度是一项工具调用；多个写调用会逐项重新确认。
- 工具执行器属于 `httpapi`，增加工具时必须同时评审命令、参数、确认和回滚策略。
